### BUG-01: Dead Code — Duplicate `return` Statement in `find_all_files()`

**Severity:** Critical (Functional Bug)
**File:** `security_scan.py`, line ~128
**Function:** `find_all_files()`

**Description:** There are two consecutive `return` statements at the end of `find_all_files()`:

```python
    return all_files, ext_map, name_map
    return all_files, ext_map, name_map
```

The second `return` is unreachable dead code. While this is not a runtime error (Python executes the first return), it signals a code quality issue and may indicate an incomplete refactoring where something was intended between the two returns (e.g., the `size_skipped` stderr message logic).

**Impact:** No functional impact — the function returns correctly. However, the presence of unreachable code is a code smell that suggests the function body may have been improperly edited. In a CI pipeline with `flake8` or similar, this would trigger a `F703` (return outside function) or dead code warning depending on the linter.

**Suggested Fix:** Remove the duplicate `return` statement.

### BUG-02: Discovery Cache Loaded as `None` When File Exists But is Empty

**Severity:** High (Functional Bug)
**File:** `security_scan.py`, lines ~540–548
**Function:** `run_discovery()`

**Description:** When the discovery cache file exists but contains empty content (0 bytes), `json.load()` raises `json.JSONDecodeError`, which is caught and triggers a re-run. However, if the file contains `"null"` or `"0"`, `json.load()` succeeds and returns `None` or `0`, respectively. The returned value is then used as a dict without type checking, causing an `AttributeError` on `.get()` calls.

```python
if not redetect and discovery_cache.exists():
    print("[DISCOVERY] Using cached discovery results")
    try:
        with open(discovery_cache) as f:
            return json.load(f)  # Could return None, int, etc.
    except (OSError, json.JSONDecodeError) as e:
        print(f"[DISCOVERY] Cache unreadable ({e}); re-running discovery")
```

If `json.load(f)` returns `None` (from a file containing just `null`), the function returns `None` directly to the caller (`main()`), which will then fail when `discovery_map.get(scanner_id, ...)` is called.

**Impact:** Scanner crashes if the discovery cache is corrupted to contain `null`, `0`, or any non-dict JSON value.

**Suggested Fix:** Add a type check after `json.load()`:

```python
result = json.load(f)
if not isinstance(result, dict):
    print(f"[DISCOVERY] Cache contains non-object JSON ({type(result).__name__}); re-running")
else:
    return result
```
