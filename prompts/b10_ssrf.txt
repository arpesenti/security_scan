Analyze this source code file for **Server-Side Request Forgery (SSRF)** vulnerabilities (OWASP B10:2025).

Look for:
- User-controlled URLs passed to HTTP clients (HttpClient, urllib, requests, curl, NSURLConnection)
- URL-based file inclusion or document loading from user input
- Redirect vulnerabilities that bypass URL validation (following redirects to internal addresses)
- DNS rebinding vulnerabilities (no DNS result validation, trusting DNS without caching)
- Internal network access via user-controlled URLs (127.0.0.1, 10.x.x.x, 192.168.x.x, 172.16-31.x.x)
- Cloud metadata endpoint access (http://169.254.169.254 for AWS/Azure/GCP metadata)
- Protocol-based SSRF (gopher://, dict://, file://, php://, expect:// wrappers)
- URL parsing vulnerabilities (IPv6, Unicode, double-encoding bypasses)
- Image/document processing from user-supplied URLs without validation
- Webhook endpoints that accept arbitrary callback URLs
- Proxy functionality that forwards requests to user-specified destinations
- Missing allowlist/ denylist for outbound connections
- SSRF via file upload (metadata extraction from remote URLs)
- SSRF via API that fetches external resources (RSS feeds, social media embeds)
- Insufficient validation of hostname vs resolved IP address

For each vulnerability found, report:
1. Line number(s)
2. The vulnerable code snippet
3. Severity (Critical/High/Medium/Low)
4. Brief explanation of the SSRF vulnerability
5. Suggested fix
6. The taint path as two fields: "source" (where untrusted input enters —
   request param, argv, socket read, queue message, env var, file upload...) and
   "sink" (where it becomes dangerous — SQL execute, shell exec, deserialization,
   HTML output, HTTP request...). Both fields are REQUIRED strings; if you
   cannot name a concrete source, the finding must not be emitted.

Do NOT flag these safe patterns (negative evidence — a finding without a
concrete source/sink taint path is worse than a missed one):
- Parameterized queries, prepared statements, and ORM/query-builder calls
- Logging of constant or internal strings (no untrusted data in the format)
- Values that never cross a trust boundary (hardcoded config, internal
  constants, values that stay inside a single trusted module)
- Test fixtures and test-only code paths
- Defense-in-depth wrappers that already validate/escape their inputs
